## 1. Apple CarPlay (new feature)

Built on `@iternio/react-native-auto-play` (Nitro, new-architecture compatible).
Developed on `feature/carplay`, now merged to `main`.

### Menu flow (works on the CarPlay Simulator)
`Main menu (List)` → My Routes / Looped Ride / Search Location / Points of Interest.
- **My Routes** — saved routes + sample routes → route preview.
- **Looped Ride** — pick a distance → round trip from current GPS (`lib/roundtrip`).
- **Search** — geocode search via Nominatim (`lib/geocode`), debounced.
- **POIs** — category → nearest 12 by distance (`lib/pois`).
- Route preview is a single `InformationTemplate` with distance/stops, an in-place
  Fastest/Curvy toggle, and a **Start ride** action (kept flat to respect CarPlay's
  5-template stack limit).

### Phone → CarPlay live ride sync
- **New `mobile/lib/active-ride.ts`** — dependency-free shared store (same JS runtime
  as the phone). Holds route coords, waypoints, live position/heading/speed, distance
  travelled, current maneuver, full turn-by-turn step list, and current step index.
- **`mobile/app/ride/[id].tsx`** — drives the store: `startActiveRide` on ride start,
  `updateActiveRide` in the location watcher, `endActiveRide` on stop + unmount. Added
  refs (`navStepsRef`, `currentStepIdxRef`, `nextWaypointIdxRef`, `distanceTravelledRef`)
  and effects to mirror route + steps while riding.
- **`mobile/src/carplay/AutoPlay.tsx`** — `LiveRideMap` component follows the rider;
  `showLiveRide` / `syncLiveRide` switch CarPlay to the live view when a ride starts.

### Native turn-by-turn (real hardware)
- On device, the live `MapTemplate` starts a CarPlay **navigation session**:
  `startNavigation(trip)` once, then `updateManeuvers` + `setManeuverState` per tick.
- OSRM maneuver `type`/`modifier` mapped to CarPlay `ManeuverType` / `TurnType`, with
  MaterialIcons turn glyphs; traffic side set to **Left** (UK).
- `setManeuverState` (continue → initial → prepare → execute) derived from distance to
  the next turn, for the instrument cluster / HUD.

### Key fixes made during development
- **Freeze fix:** the phone streams location several times/sec; refreshing CarPlay on
  every update flooded the template bridge and froze the UI. Throttled the car-side
  refresh to once per second (`LIVE_UPDATE_MS = 1000`).
- **Auto-open fix:** `didConnect` does not re-fire if CarPlay is already attached when
  the JS (re)loads, so `registerAutoPlay` now also reads `HybridAutoPlay.isConnected()`
  and resumes the active ride / main menu.
- **Diagnostics** (`[CarPlay] …`) gated behind `__DEV__` so release builds stay quiet.

### Known constraints (documented in `mobile/CARPLAY.md`)
- **iOS 26 Simulator crashes on `MapTemplate`** (Apple `CarPlayTemplateUIHost` bug:
  `vehicleSupportsDestinationSharing` unrecognized selector). The map + native
  turn-by-turn are therefore gated to `Device.isDevice`; the simulator shows a live
  status `InformationTemplate` card instead.
- CarPlay allows at most **5 templates** on the stack.
- A CarPlay app **cannot self-foreground** except via an active navigation session
  (needs `MapTemplate`), so auto-foreground-on-Start works on **hardware only**.
- The head-unit scene always mounts the RN root `AutoPlayRoot` (registered via
  `AppRegistry`).

## 3. App Store review fix — ITMS-90683 (missing purpose string)

Apple rejected the build for a missing `NSSpeechRecognitionUsageDescription`. Cause:
the `@iternio` CarPlay library compiles in `SFSpeechRecognizer` and `AVAudioSession`
mic-record code for hands-free voice input, so a purpose string is required even
though VisorUp does not actively use it (our own voice-nav is text-to-speech only).

Fix (`ec3b09b`) — added to `mobile/app.json` → `ios.infoPlist`:
- `NSSpeechRecognitionUsageDescription`
- `NSMicrophoneUsageDescription` (same library references mic APIs; added proactively
  to avoid a second rejection)

Resubmit: `eas build --platform ios --profile production` (prebuild regenerates the
Info.plist with the keys) then `eas submit --platform ios --latest`.

## 5. Age rating — new "social media" questions

Apple added age-rating questions about **social media capabilities** (defined as
redistributing, amplifying, or interacting with user-generated content via a social
feed). Required for submissions from **September 2026**.

VisorUp qualifies (community feed with posts/comments, route publishing, ride
sharing, group riding, profiles, plus report/block moderation). Recommended answers:
- "Does your app include social media capabilities?" → **Yes**
- "Are these capabilities disabled for users under 13?" → **No** (no under-13 age gate)

Result: a **Social Media** content descriptor and a minimum **13+** rating (fine for a
motorcycle touring app). These questions live in **App Information** (app-level) and
can be answered **without removing the in-review build**.
